# Life Manager

> 一个默认纯本地的个人生活与工作管理应用。今日计划、书房（读书 + 写作）、开发工作、健康（健身 + 饮食）、
> 成长（习惯 + 目标 + 日记）、统计与复盘，加上首页总览与游戏娱乐。
> 默认没有账号、没有后端、没有网络请求 —— 数据只存在你自己的浏览器里，导出来就是一个 JSON 文件。
> 跨设备同步是 V2.0 的可选能力（见 [`docs/adr/0002`](docs/adr/0002-跨设备同步以本机服务实现，纯本地降为默认.md)），默认关闭，关闭时仍是零网络请求。

## 当前版本：v2.0.0

**跨设备同步**：一个可选的同步服务 + 客户端引擎。默认仍然是纯本地、零网络请求；
开启之后，多台设备通过**你自己机器上跑的一个 Node 进程**交换数据。

- **服务端**（`src/server/`，零新依赖）：`npm run sync` 或双击 `src/server/start-sync-server.bat` 起。
  冲突按**条目 last-write-wins**、由服务端定序；删除留墓碑并传播；自带每日备份、
  历史版本与 `/v1/restore` 回滚；可选第二份存储（`mirrorDir`）。
- **客户端**：设置页「跨设备同步」卡（开关 / 地址 / 令牌 / 立即同步 / 重新对账）。
  关闭时**连同步代码都不会加载**（动态 import），首屏体积不受影响。
- **令牌只存在本机**：不进备份、不进导出、**也不进自动快照**（`appStorageKeys()` 单独排除）。

**不丢数据**：`STORE_VERSION` 仍是 **12** 未动 —— 客户端存档结构没变，v1.0.0 / v1.1.0 的存档
与导出 JSON 可以直接用。`BACKUP_SCHEMA_VERSION` 从 19 升到 **20**（V2.0 期间补了
饮食的每日目标与饮水打卡进备份，修一个导出再导入会静默丢数据的 bug）；老备份继续可读，
导入时按「模块缺失」处理，**不会清空本机数据**。逐条变更见 [CHANGELOG.md](./CHANGELOG.md)。

## 为什么默认「纯本地」

个人数据（读了什么书、写了多少字、练了什么、吃了什么）默认不经过别人的服务器。所以这个项目：

- **默认没有后端**：`npm run preview` 出的静态文件丢到任何地方都能跑。V2.0 起可选开启自建同步服务
  （跑在你自己的机器上），**关闭时仍然是零网络请求**。
- **断网也能用**：装了 service worker，首次打开之后断网照常使用，也可以装成桌面 / 手机应用。
- **默认没有账号**：打开即用，没有登录、没有遥测。开启同步后需要一个访问令牌 ——
  同步只服务你自己的多台设备，不做注册、不做分享、不做协作。
- **数据可带走**：一键导出 JSON，导入时还能选「合并」或「覆盖」。
- **不吞数据**：任何破坏性操作前都会自动留快照；「清除数据」也保留快照，随时能回滚。
  代码里没有 `localStorage.clear()`。

> V2.0 解除了「绝不引入后端」这条 V1 硬约束：纯本地从硬约束降为**默认形态**，跨设备同步可选开启。
> 取舍、代价与回滚条件见 [`docs/adr/0002`](docs/adr/0002-跨设备同步以本机服务实现，纯本地降为默认.md)。

## 技术栈

React 18 + TypeScript（严格模式，禁用 `any`）+ Vite 6 + Tailwind CSS 3 + zustand（`persist`）+ react-router + zod + @dnd-kit。
依赖刻意保持克制：没有 UI 组件库、没有图表库、没有日期库的重度封装，图表与设计系统都是自己写的。
PWA 也没引 workbox —— 离线壳是一个手写的 service worker（`public/sw.js`，约 100 行），
图标由 `scripts/generate-icons.mjs` 用 Node 自带的 zlib 直接生成 PNG，同样没有引入原生依赖。

外观系统是三层叠加：**明暗**（`data-theme` 经由 Tailwind 的 darkMode: 'class'）×
**主题色**（5 个预设，`data-accent` 覆盖块）× **皮肤**（`data-appearance`：默认「流光玻璃」
—— 半透明表面 + 环境光晕 + 粘性浮层磨砂；「纸面扁平」是换肤前的素底平卡片，可在设置页切回）。
动效全站只用 CSS：路由入场、级联进场、悬停微抬升、状态点呼吸，系统开了「减弱动态效果」时
全部停用（组件级 `motion-reduce:` 加全局兜底双保险）。两套皮肤 × 明暗的文字对比度都在
`tokens.test.ts` 里按 WCAG AA 逐对核验。

## 装成应用（PWA）

`npm run build && npm run preview`，用浏览器打开预览地址，地址栏右侧会出现「安装」按钮；
手机浏览器里是「添加到主屏幕」。装完之后：

- 独立窗口运行，没有浏览器地址栏；
- 断网可用（数据本来就在本地，service worker 只负责把页面壳也缓存下来）；
- 换新版：导航请求走网络优先，重新打开就会拿到新版本，不用手动清缓存。

离线壳只缓存 HTML / CSS / JS / 图标，**不碰任何用户数据**（既不读也不写 localStorage / IndexedDB）。

```bash
npm install

npm run build      # 类型检查 + 生产构建
```

## 数据与隐私

- 所有数据存在浏览器本地：优先 **IndexedDB**（配额按 origin 算，起步几百 MB），拿不到 IndexedDB
  （Safari 隐私模式、被别的标签页占着）时整条链路退回 `localStorage`。数据 key 统一带 `lm:` 前缀，
  方便「只清本应用的数据」。
- **首启自动搬家**：第一次在支持 IndexedDB 的环境打开时，会把 localStorage 里的老数据搬进 IndexedDB，
  **只写不删** —— 老副本留在原处，是出问题时的回溯依据。
- **每日自动快照**：每天第一次打开应用时会留一份快照，最多保留 10 份，可在「数据与设置」里回滚。
- **备份到指定文件夹**（Chrome / Edge 桌面版）：在设置页把一个文件夹的写权限交给应用，之后每次打开都会
  静默覆盖里面那份 `life-manager-auto-backup.json`。全程本地读写，不上传；文件夹授权随时可以取消，
  已经写出去的文件不会被删掉。不支持这个 API 的浏览器会提示改用「导出 JSON」。
- **导入 / 导出**：导出是完整 JSON（含外观设置）；导入前会校验并给出预览，再选合并或覆盖。
- **数据体积**：设置页会显示当前占用；落在 IndexedDB 时按 origin 配额告警，退回 localStorage 时按约 5MB 的
  上限告警。
- **升级不丢数据**：读出来的旧数据会逐条归一化到当前结构，缺字段补齐、坏记录丢弃而不是让页面崩掉。

## 质量门

| 命令                   | 作用                                                           |
| ---------------------- | -------------------------------------------------------------- |
| `npm run typecheck`    | TypeScript 全量类型检查（`tsc -b`）                            |
| `npm run lint`         | ESLint（含 `jsx-a11y` 全量规则）                               |
| `npm run format:check` | Prettier 全仓格式检查                                          |
| `npm run test`         | vitest 单元与组件测试（2025 条 / 122 个文件）                  |
| `npm run build`        | 生产构建                                                       |
| `npm run size`         | 首屏 gzip 体积预算（≤ 300KB，构建后跑）                        |
| `npm run e2e`          | 真浏览器冒烟（35 条，需本机 Edge，不进 CI）                    |
| `npm run sync`         | 起同步服务端（默认 `127.0.0.1:8787`）                          |
| `npm run sync:e2e`     | 服务端端到端验收（17 条，起一个真服务端打 HTTP）               |
| `npm run e2e:sync`     | **两设备实机冒烟**（19 条：两个隔离 profile + 真服务端，见下） |

CI（`.github/workflows/ci.yml`）按 `typecheck → lint → format:check → test → build → size` 顺序跑。
`npm run e2e` 与 `npm run e2e:sync` 只在本地跑 —— 它们驱动本机 Edge，CI runner 上没有，
详见 `e2e/README.md`。

> **`npm run e2e:sync` 是上线前那一关，单测替代不了。** 它起两个**彼此隔离**的浏览器 profile
> （各自的 IndexedDB 与令牌）加一个真在监听端口的服务端进程，走完整流程：开开关、填令牌、
> A 写 B 拉、制造一次真冲突看那行提示、删除跨设备传播。单测里那套「两个 store 对象」
> 是同一份内存的两种看法 —— 验不出「令牌是不是真的只在本机」「关掉开关是不是真的零请求」。
> 它已经抓出过一个单测与截图都漏掉的缺陷（冲突明细缺「服务端那份的时间」）。

> `format:check` 已经在门禁里：全仓格式化在导航收敛收尾时做过一次（清掉 29 个历史文件），
> 之后改完直接 `npx prettier --write .` 就行。

## 快捷键

| 按键           | 作用                                            |
| -------------- | ----------------------------------------------- |
| `Ctrl / ⌘ + K` | 打开命令面板（跳页面、切换外观）                |
| `/`            | 打开命令面板并直接搜索                          |
| `n`            | 新建当前模块的条目                              |
| `g` 后接 `1-9` | 跳转到对应主页面（1 首页、2 今日计划、3 书房…） |
| `j` / `k`      | 列表里在上一条 / 下一条之间移动焦点             |
| `x`            | 把焦点所在的那一行勾进批量操作                  |
| `Esc`          | 关闭弹层与抽屉                                  |

命令面板里可以直接录入：`写周报 !高 @明天 #工作`（`!` 优先级、`@` 日期、`#` 标签），
输入 `#工作` 则跨模块列出所有打了该标签的记录。

`j` / `k` / `x` 只在焦点落在列表里时生效（书房 / 游戏 / 任务三页），不抢全局按键。
