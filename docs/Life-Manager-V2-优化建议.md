# Life Manager V2 优化建议

> 来源：GitHub 同类项目调研（2026-09-29）+ `E:\MyApp` 源码逐文件走查
> 现状基线：10 个功能模块 + 统计页、约 7900 行页面代码、404 个单测全绿、`STORE_VERSION = 11`
> 本文档定位：给 V2 定方向、排优先级、划边界。它不是"功能清单"，是"取舍清单"。

---

## 0. 结论先行

V1 的**地基**已经超出个人项目的平均水准：语义化设计令牌 + WCAG 对比度测试、20+ 个带完整状态的 UI 组件、zod 校验 + 三种合并策略的导入导出、`lm:` 前缀隔离的存储键、路由分包、无障碍专项、404 个单测。**这些不要推翻。**

但走查完各模块页之后，问题也很清楚：它现在更像**"9 个互不相通的记录表单"**，而不是一个每天愿意打开的个人系统。三个洞：

1. **录入摩擦**：每个模块都要"点新建 → 弹窗 → 填 5 个以上字段 → 保存"。个人工具的第一杀手就是录入成本。
2. **模块孤岛**：没有标签、没有跨模块搜索、没有关联。`CommandPalette` 目前只做"跳转 + 切换外观"，`fuzzyFilter` 只用在这里。
3. **数据托底不足**：全部数据在 localStorage（约 5MB 上限），9 个 `persist()` 都没配 `onError`，写入超限不会提示；没有 PWA（`public/` 是空的，`index.html` 无 manifest / service worker），清一次浏览器数据就全丢。

另外，V1 强在**记录**，弱在**计划**与**复盘**：没有时间盒、没有专注计时、没有每日/每周复盘、没有目标。而这恰恰是同类产品留住用户的环节。

### 如果只做 5 件事（按性价比排序）

| #   | 事情                                                                                                                   | 为什么排前面                                                                                             | 规模 |
| --- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---- |
| 1   | **命令面板升级成"万能操作台"**：⌘K 既能搜到实体（任务/书/项目/笔记），也能直接执行动作（新建任务、记一笔训练、写备忘） | 一个组件解决所有模块的录入摩擦，改动集中、收益全局                                                       | 中   |
| 2   | **数据层加固**：IndexedDB + 自动快照 + 配额预警 + PWA 可安装                                                           | 现在"清缓存 = 全丢"，对天天用的工具是致命风险                                                            | 中   |
| 3   | **首页改成可配置仪表盘 + 今日时间轴**                                                                                  | 首页决定"这工具是不是我的主场"，现在它只是个导航页                                                       | 中   |
| 4   | **统一标签 + 跨模块全局搜索**                                                                                          | 打破孤岛，让 9 个模块成为一个整体                                                                        | 中大 |
| 5   | **习惯打卡模块 + 体重/围度**                                                                                           | 习惯是回访率最高的功能；体重是健身模块现在**承诺了却没做**的事（`navItems.ts` 写着"训练记录与身体指标"） | 小中 |

### 1.1 具体可抄的点

- **super-productivity**：任务可以"拖到时间轴"成时间盒；有专注计时器和休息提醒；一天结束自动生成"今天做了什么"。→ 对应 F3、F7。
- **uhabits**：习惯不是"连续 N 天"，而是**强度分数**（近期完成率加权），断一天不会归零。→ 对应 F4，比"连续打卡"更抗挫。
- **wger / Ryot**：都靠"**种子数据库**"解决冷启动——动作库、食物库、媒体条目库。手填一切是 V1 最大的录入成本来源。→ 对应 F9、F10。
- **life-os**："解析失败就把原文存下来并标记待整理，输入永不丢失"。这个降级思路可以用在本地规则解析的快录上。→ 对应 F1。
- **dashy**：首页 widget 可增删、可调尺寸、可分组。→ 对应 U1。
- **beaverhabits**：打卡不需要弹窗——点格子即可切换，这是"日更类"功能的标准交互。→ 对应 U4。

### 1.2 明确不要抄的

- **不要抄 Habitica / HabitTrove 那类游戏化**（金币、宠物、排行榜）：单人自用工具里，游戏化很快会变成负担。
- **不要抄 Life OS 的 AI Chat**：需要联网、需要 Key、效果不稳定，与"纯本地"约束冲突。
- **不要抄 dashy 的完整复杂度**（widget 配置中心、多主题包）：我们只需要"一个能调的首页"。

## 2. 现状诊断

### 2.1 已经做扎实的（V2 不要推翻）

| 方面     | 证据                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 设计令牌 | `src/styles/tokens.css` 定义全部语义色，`tokens.test.ts` 按 WCAG 逐对核验对比度                               |
| 组件库   | `src/components/ui/` 导出 20+ 组件，含五态、焦点环、`motion-reduce:animate-none`                              |
| 数据安全 | `src/services/backup.ts` + `schemas.ts`：zod 校验、逐条降级解析、三种导入策略、去重、`lm:` 前缀隔离、快照回滚 |
| 迁移     | `src/store/persist.ts` + `STORE_VERSION = 11`，每步变更都有注释记账                                           |
| 工程     | 路由分包 + 骨架屏、ErrorBoundary、a11y 专项、ESLint + Prettier、404 单测 / 32 文件                            |

### 2.2 四个核心短板（附证据）

**短板一：录入摩擦高**
每个模块都是"Card 列表 + Modal/Drawer 表单"，表单动辄 5+ 字段（如 `src/pages/FitnessPage.tsx` 的动作行编辑）。快速记录一个想法要跨越 3 次点击 + 1 个弹窗。全站唯一的"零摩擦"入口是首页的快速备忘和 `parseQuickTask`（`src/utils/quickParse.ts`），但只覆盖任务。

**短板二：模块孤岛**

- `src/components/layout/CommandPalette.tsx` 的命令只有两类：`跳转` 与 `外观`，没有实体检索、没有创建动作。
- 搜索是**每页各写一份** `filterByKeyword`（Books / Dev / Fitness / Diet / Games / Writing 各引一次），只能搜自己模块。
- 没有标签系统：`src/types/index.ts` 里没有任何 `Tag` / `tags` 字段，也没有跨模块引用（只有 `ReadingSession.bookId`、`WorkSession.projectId`、`GameSession.gameId` 这类从属关系）。

**短板三：数据托底不足**

- 9 个 `persist()`（task / book / dev / writing / fitness / diet / game / theme / ui）都只传了 `name` + `version` + `migrate`，**没有 `onError`**；localStorage 写入超限（5MB 上限、Safari 隐私模式）时用户不会收到任何提示。
- `public/` 目录为空：无 manifest、无图标、无 service worker → 不能安装成桌面/手机应用，断网不可用。
- `migrateState()` 是**顶层浅合并**：只能补"store 根级"的缺失字段。数组内单条记录新增的字段（例如给 `Task` 加 `subtasks`）不会被回填，只能靠各页面写 `task.subtasks ?? []` 兜底——这就是 `src/types/index.ts` 里到处是"旧数据可能没有"注释的根因。

**短板四：缺"计划—专注—复盘"闭环**
V1 有：任务（列表/看板/四象限）、工时流水、阅读/游玩流水、热力图、趋势图。
V1 缺：时间盒、专注计时、每日总结、每周复盘、目标与达成率。`src/pages/StatsPage.tsx` 是"看历史"，不是"改进下一天"。

### 2.3 文档与实现的两处漂移（顺手修）

- `src/components/layout/navItems.ts` 里健身的描述是"训练记录与身体指标"，但 `src/types/index.ts` 没有任何体重/围度类型，页面上也没有入口。
- `docs/产品设计文档.md` 仍写着"不支持手机端"，但 P6-3-1 已做移动端适配。

## 3. 功能建议

每条包含：目标 / 参考 / 数据影响 / 主要涉及文件 / 验收。优先级按"是否阻塞日常使用"排。

### P0 —— V2.0 必须做

#### F1 全局快速捕获（把录入压到一次输入）

> **状态：已在 V2.0 第二阶段落地**，实现细节与规则表见第 9 节。

- **目标**：任意页面 ⌘K → 输入一句中文 → 回车落库。例如 `明天 交周报 !高 #工作`、`跑步 30min`、`《置身事内》读到 120 页`。识别不了的输入**存成备忘并提示归类**，绝不丢内容。
- **参考**：life-os 的 capture（解析失败降级保存）、super-productivity 的 quick add。
- **做法**：`src/utils/quickParse.ts` 现在只解析任务；扩成"模块前缀 + 日期 + 优先级 + 标签 + 数值"的规则解析器（纯本地正则，不引 AI）。识别到模块就调对应 store 的 `add*`，否则落备忘。
- **涉及**：`src/utils/quickParse.ts`、`src/components/layout/CommandPalette.tsx`、各 `src/store/*.ts`、`src/components/ui/Toast.tsx`。
- **验收**：6 类前缀句式都能正确落库；无法识别时内容进入备忘且有提示。

#### F2 统一标签 + 跨模块全局搜索

> **状态：已在 V2.0 第三阶段落地**（数据层 commit `21a1cdd`，页面接入为本次提交）。
> 落地时对下面这条计划的调整写在**落地时调整**里，完整取舍见第 9 节。

- **目标**：一套标签贯穿所有模块；⌘K 能搜到实体（任务 / 书 / 开发项目 / 写作 / 训练记录 / 备忘），回车直达对应详情。
- **数据影响**：7 类实体加 `tags?: string[]`；新增 `lm:tags` 存标签颜色等元数据；`STORE_VERSION` → 12。
- **落地时调整**：`tags` 做成**必填**（由归一化层每次水合补齐，页面里不用写 `?? []`）；**不建** `lm:tags`
  元数据表，配色改由标签名哈希决定；版本号 bump 的是 `BACKUP_SCHEMA_VERSION`（10 → 11）而不是 `STORE_VERSION`，
  因为这是「数组内单条记录加字段」，升 `STORE_VERSION` 反而会让一次性迁移代码跑不到。
- **注意**：`migrateState()` 是顶层浅合并，**回填不了数组内单条记录的新字段**。这一步必须同时落地 D4 的归一化层，否则又要在每个页面写 `?? []`。
- **涉及**：`src/types/index.ts`、各 `src/store/*.ts`、`src/utils/search.ts`（扩成可复用的检索索引）、`src/components/layout/CommandPalette.tsx`。
- **验收**：搜"健身"能同时命中打了该标签的任务、书与项目；单测覆盖跨模块检索与去重。

#### F3 今日时间轴 + 专注计时

- **目标**：把今天的任务拖到 06:00–24:00 时间轴上形成时间盒；选中一项启动计时（番茄钟 / 正计时），结束后可一键完成任务，并把时长回填到开发工时 / 阅读 / 游玩流水。
- **参考**：super-productivity（时间盒 + 专注模式 + 休息提醒）。
- **数据影响**：新增 `src/store/focusStore.ts`（会话：`entityId`、`startedAt`、`minutes`、`mode`）；`Task` 增加可选时间盒字段。
- **涉及**：新 `src/components/timeline/`、`src/pages/TasksPage.tsx`、`src/store/taskStore.ts`。
- **验收**：拖拽生成的时间盒刷新后仍在；计时结束可一键完成并写入流水。

#### F4 习惯模块

- **目标**：新建习惯（每天 / 每周 N 次 / 自定义间隔），首页与习惯页都能**点格子直接打卡（无弹窗）**；用"习惯强度分数"（近期完成率加权）而非单纯连续天数；支持量化习惯（喝水 8 杯）。
- **参考**：uhabits 的强度模型、beaverhabits 的零弹窗打卡。
- **数据影响**：新增 `src/store/habitStore.ts`：`Habit { id, name, kind: 'binary' | 'count', target, schedule, logs: Record<dateKey, number> }`。
- **涉及**：新 `src/pages/HabitsPage.tsx`、`src/components/layout/navItems.ts`、`src/pages/HomePage.tsx`。
- **验收**：点格子即写入且可撤销；断签不清零；首页显示今日未打卡习惯。

#### F5 体重与身体围度（兑现已有承诺）

- **目标**：体重 / 体脂 / 围度（胸腰臀臂腿）按日记录 + 趋势图 + "较上次 ±x kg"。
- **参考**：wger、Ryot 的 measurements。
- **数据影响**：新增 `src/store/bodyStore.ts`：`BodyMetric { id, date, weight?, bodyFat?, measurements: Record<string, number> }`。
- **涉及**：`src/pages/FitnessPage.tsx`、`src/components/charts/`、`src/components/layout/navItems.ts`（文案与实现对齐）。
- **验收**：新增一条体重后，趋势图与"较上次"数值正确。

## 4. UI / UX 建议

### U1 首页：从"卡片墙"到可配置仪表盘

- **状态：已落地**（V2.0 第四阶段）。代码在 `src/components/dashboard/DashboardGrid.tsx` + `src/store/uiStore.ts` 的 `dashboard`。
- **现状（改造前）**：`src/pages/HomePage.tsx` 是固定顺序的卡片墙；内容区固定 `max-w-5xl`（`src/components/layout/Layout.tsx`），宽屏浪费大半空间。
- **建议**：
  - 12 栏栅格 + 卡片尺寸（1x1 / 2x1 / 2x2），支持拖拽排序与隐藏，配置存 `lm:ui`。
  - 新增 widget：今日时间轴、专注计时、习惯打卡条、目标达成环、快速捕获、最近编辑。
  - 仪表盘与统计页允许宽版布局（`max-w-7xl`）。
- **参考**：dashy。
- **验收**：增删 / 重排后刷新保持；窄屏自动降为单列。

**落地时调整（原建议保留，这里说明为什么做得不一样）**

- **宽度分档，不做 1x1 / 2x2**：卡片高度全由内容决定，硬要「两行高」就得给每张卡定死高度，内容一多就出
  滚动条。改成 12 栏里的「小 4 栏 / 中 8 栏 / 宽 12 栏」，拿到同样的排版自由度又不用和高度打架；
  小 + 中正好凑满一行，用户也不用数格子。
- **只存 `{ id, size, hidden }`**：卡片叫什么、渲染成什么样都属于代码。以后改文案、换卡片内容都不会让用户
  排好的布局失效；新增卡片时 `normalizeDashboard()` 会把缺的补到末尾，用户不必手动点一次「恢复默认」。
- **编辑态才渲染「暂时没数据的卡片」**：平时「没有活动就不显示空热力图」这条规则保留（空卡片不占屏），
  但进编辑态一律显示成占位卡 —— 否则用户没法把一张当前没数据的卡片拖走或隐藏。
- **没做宽版布局（`max-w-7xl`）**：`Layout.tsx` 的内容宽度是全站共用的，只给首页放宽会出现「同一份内容
  在两个页面宽度不同」的割裂感。等 U2 双栏重新定义内容区宽度时一起处理。
- **今日时间轴 / 专注计时 / 目标达成环等新 widget 没做**：先把「可配置」这件基础能力铺好，新卡片属于
  V2.1 的内容增量。

### U2 桌面端用"列表 + 详情"双栏替代弹窗

- **状态：组件已落地，读书页已接入**（V2.0 第五阶段）。代码在 `src/components/layout/MasterDetail.tsx`，首个接入页 `src/pages/BooksPage.tsx` 的读书笔记。
- **现状（改造前）**：所有模块都是"列表 + Modal / Drawer"；但 `src/pages/DevProjectPage.tsx` 已经是独立详情页，说明这个模式在本项目里可行。
- **建议**：≥1280px 用 master-detail（左列表 + 右详情面板，详情直接复用现有表单组件，内联保存）；窄屏保留弹窗 / 抽屉。
- **收益**：编辑不再打断上下文，可连续处理多条（Linear / Things 的核心体验）。

**落地时调整**

- **不用 CSS 的 `hidden` / `block` 两套 DOM**：同一个详情节点在两种模式下只渲染一次，靠
  `useMediaQuery('(min-width: 1280px)')` 选分支。否则详情里的输入框会在 DOM 里出现两份，
  读屏读两遍、id 也会重复（`a11y.test.tsx` 会直接抓出来）。
- **宽屏右栏是「常驻」的**：没选中项时显示占位内容，而不是整栏消失。这样点左边某一条时右侧不会
  「突然挤出来」，列表宽度也不会跳。
- **内容区宽度跟着分支走**：`Layout` 从 `max-w-5xl` 改成 `xl:max-w-6xl 2xl:max-w-7xl`。
  这解决了 §4 U1 里留下的「只给首页放宽会让两个页面宽度不一致」的问题 —— 宽度是全局的一档，
  窄屏不变、宽屏才多出这一两百像素，刚好够放下 24rem 的右栏。
- **其余页面留给 V2.1**：每页的详情落点不同（游戏是成就与游玩流水、健身与饮食是「一天」的汇总），
  套用同一个组件要先想清楚「详情是什么」，硬套反而会把页面拆坏。读书页先做样板。
- **涉及**：新增 `src/components/layout/MasterDetail.tsx`，各页面逐步复用。

## 5. 数据与工程建议

### D1 存储层：localStorage → IndexedDB（保留 localStorage 作为迁移来源）

- **为什么**：localStorage 约 5MB 上限、同步写入会卡主线程；一旦加入习惯日志（每天每习惯一条）、体重流水、正文快照与封面图，容量会迅速逼近上限。
- **怎么做**：引入 `idb-keyval`（约 600B gzip）或 `Dexie`；写一个 `createPersistedStore` 工厂（见 D4）把 zustand `persist` 的 storage 换掉，并在首次启动时把 `lm:*` 的旧数据一次性搬过去、成功后保留原 key 一段时间再清理。
- **约束**：迁移必须可回退、必须幂等；`docs/技术方案.md` 与 `STORAGE` 说明同步更新。

### D2 写入可靠性

- 给所有 `persist()` 补 `onError`（现在一个都没有）：写入失败要弹 Toast 并提示"数据可能未保存，建议立即导出备份"。
- 增加 `lastWriteAt` 与"待写入"指示；`Header` 的手动保存按钮已存在，可与自动状态合并成一个可信的保存状态。
- 用 `navigator.storage.estimate()` 在设置页给出"已用 / 可用"，超过 70% 时预警。

### D3 自动备份与落盘

- 现有：每次改动自动写 localStorage + 手动快照（`src/services/backup.ts`，保留 N 份）。
- 建议：① 按日自动生成一份快照，与手动快照分池、保留 14 天；② 提供"导出到指定文件夹"（File System Access API，Chrome / Edge 可用，纯本地不联网），记住目录句柄后每次打开应用静默写一份；③ 设置页显示最近一次备份时间与一键恢复。
- 兜底：不支持该 API 的浏览器降级为"每周提醒导出"。

### D4 归一化层 + 统一 store 工厂

- **问题**：`migrateState()` 只做顶层浅合并，数组内单条记录的新字段回填不了，导致 `src/types/index.ts` 里到处是"旧数据可能没有"的注释、各页面到处是 `?? []`。
- **建议**：把 `src/services/schemas.ts` 已有的 zod schema 复用到读取路径上——每条记录 `schema.parse()` 后得到补齐默认值的对象；写一个 `createPersistedStore({ name, version, schema, migrate, defaults })` 工厂，集中处理 `onError` / 配额 / 版本 / 归一化。9 个 store 收敛成 9 行配置。

### D5 页面抽象，削减重复代码

- **现状**：12 个页面文件共约 7900 行，最大 `DevPage.tsx` 878 行、`TasksPage.tsx` 777 行；页面结构高度同构（PageHeader + Toolbar + 筛选 + 列表 + Modal）。
- **建议**：抽出 `EntityListView`（列表 / 空态 / 筛选 / 排序 / 多选 / 键盘导航 / 详情容器由配置驱动），各页面只写"字段定义 + 卡片渲染 + 表单"。预计可减少 30%–40% 页面代码，同时 U2/U3/U4 的能力自动惠及所有模块。

### D6 CI 与质量门

- 新增 `.github/workflows/ci.yml`：`typecheck → lint → test → build`，并加体积预算（首屏 gzip ≤ 300KB，当前分包已具备基础）。
- 可选：`vitest --coverage` 覆盖率门槛（行覆盖 ≥ 70%），先只对 `src/utils` 与 `src/services` 生效，避免为了数字写无效测试。

### D7 补齐项目门面

- 根目录目前**没有 `README.md`**、没有 `LICENSE`、没有 `.github/`。README 至少写：这是什么、怎么跑、数据存在哪、如何备份与恢复、V2 路线图。

### D8 E2E 冒烟测试（Playwright）

- 现在 404 个单测都是组件 / 纯函数级，缺"真浏览器里跑通一条链路"的保障。补 5 条关键用例即可：
  1. 新增任务 → 勾选完成 → 刷新后仍在；
  2. 导出 → 清空 → 导入 → 数据完全一致；
  3. ⌘K 搜索与创建；
  4. 键盘全流程新建（无鼠标）；
  5. 375px 视口下导航抽屉与列表可用。

**三条排序规则**（决定回车时选中什么，按确定性从高到低）

3. 其他情况 → 快速捕获优先，回车把这句话落库

**几个刻意的选择**

- **标签配色不做配置**：`tagTone()` 按名字哈希出 6 档稳定配色，同一个词在任何模块、任何页面都是同一个颜色，
  不新增 `lm:tags` 存颜色。少一个数据源，就少一处「配置与数据不同步」。
- **不建「标签表」**：标签只存在各条记录自己的 `tags` 里。导入 / 导出 / 备份不用维护两张表的一致性；
  删掉最后一条带某标签的记录，这个标签自然消失，不会留下孤儿标签。
- **备忘不参与标签**：备忘是「先记下来再说」的自由文本，摘标签会破坏「原文一字不差」的承诺。
- **正文里的 `C#` 不算标签**：`extractTags` 用零宽断言 `(?<![A-Za-z0-9])[#＃]`，`#` 前面紧跟英文字母或
  数字时不识别；前面是汉字时仍然识别，所以 `写周报#工作` 也能摘出来。
- **训练 / 饮食这类流水只索引最近 100 条**（`STREAM_LIMIT`）：它们一年能积累上千条，全量进索引会让 `⌘K`
  的响应与内存占用都没有上界；100 条足够覆盖「最近在练什么 / 最近在吃什么」。
- **bump 的是 `BACKUP_SCHEMA_VERSION`（10 → 11），不是 `STORE_VERSION`（仍是 11）**：这是「数组内单条
  记录加字段」，归一化层每次 rehydrate 都会补齐；升 `STORE_VERSION` 反而会让一次性迁移代码跑不到 ——
  正是第一阶段修掉的那个坑。
- **Fitness / Diet 只做索引，没做卡片上的标签编辑器**：这两页的记录是「一条流水 + 多个动作 / 多种食物」的
  复合结构，就地编辑的落点不清晰，留给 V2.1 连同「编辑整条记录」一起做；数据层已经能存、能搜，
  `⌘K` 捕获时也能直接打标签。

  `EmptyState` 占位卡；`hidden` 的卡片两种状态都不在栅格里，只出现在底部「已隐藏」区。
- **拖拽用 `@dnd-kit` 而不是原生 DnD**：项目里 `KanbanBoard` 已经在用，键盘可操作、触屏可用、无障碍属性
  齐全，不新增依赖；也不需要 HTML5 DnD 那套 `dataTransfer` 兼容代码。
- **`lm:ui` 里只放 id 与档位，不放标题、图标、组件**：持久化数据是「用户的排布」，不是「卡片定义」。
