# Life Manager 模块合并规划

> 目标：主导航从 **13 项收敛到 8 项**，把语义相近的模块归组。
> 铁律：**只动信息架构（路由 / 导航 / 页面容器），不动数据层** —— 所有 store、schema、
> 备份模块、存储键保持原样，合并前后数据与功能零变化。

## 2. 技术方案

### 2.1 宿主页 + 嵌套子路由（路线 A，推荐）

```tsx
{/* 宿主壳就一个泛化组件，四个模块共用；阶段二已经把 StudyLayout 并进它 */}
<Route path="/study" element={<ModuleHost host="/study" />}>
  <Route index element={<Navigate to="books" replace />} />
  <Route path="books" element={<BooksPage />} />
  <Route path="writing" element={<WritingPage />} />
</Route>
{/* 旧路径保底重定向，书签与外部链接不碎 */}
<Route path="/books" element={<Navigate to="/study/books" replace />} />
<Route path="/writing" element={<Navigate to="/study/writing" replace />} />
```

- 宿主壳是**一个**泛化组件 `<ModuleHost host="..." />`：只渲染「子页签条 + `<Outlet />`」，
  **不放组名 h1**——子页面保留自己的 PageHeader，a11y 基线（每页唯一 h1）不破。
  （初稿计划「每组合并新增一个薄宿主」，阶段二合并健康时发现四个模块除了 `host` 一模一样，
  就并成一个组件了。）
- 子页签条是共用新组件 `ModuleTabs`（包一层 SegmentedControl，当前项从 location 推导，
  点击走 navigate）。
- 子页面组件**零改动**：它们不知道自己被嵌套了。

#### `ModuleTabs` 契约（定稿）

```tsx
<ModuleTabs host="/study" />   // 宿主只传一个路径，tabs 从 NAV_ITEMS 派生
```

**子页的真相源是 `MODULE_TABS`，不是 `NAV_ITEMS`。** 初稿写的是「从 `NAV_ITEMS` 按
`path.startsWith(host + '/')` 过滤得出」—— 这条走不通：`NAV_ITEMS` 收敛到 8 条之后，里面根本
不再有 `/study/books` 这样的子页路径，过滤结果恒为空。子页与「全局导航项」本来就是两种东西：
前者只在一个模块内跳转，后者要进侧栏、底部 Tab、命令面板与 `g+数字`；硬塞进同一个数组，
会让这四处都得加「排除子页」的判断。

所以 `navItems.ts` 另外导出 `MODULE_TABS`：宿主路径 → 子页 `{ path, label, icon }[]`。它同时供
三处使用 —— 签条渲染、顶栏标题、读屏播报（后两处让播报念「读书」而不是「书房」）。

`NavItem` 的既有字段语义**不动**，只加了一个可选 `host`（实施时的补充）：`path` 仍然是「点一下
去哪儿」，合并后的宿主把它指向默认子页 `/study/books`（§2.3 定的节奏），于是激活态不能再拿
`path` 当范围用 —— 否则停在 `/study/writing` 时侧栏里的「书房」会灭掉。`host` 就是宿主用来圈
范围的模块前缀，`isNavItemActive` 相应地从「收路径字符串」改成「收导航项」。

当前项从 `location.pathname` 精确匹配得出；点击走 `navigate(path)`（**push**，与侧栏、底部 Tab
点击一致）。底层复用既有 `SegmentedControl`（`src/components/ui/SegmentedControl.tsx:24`），
其 `role=group` + `aria-label` + `aria-pressed` 语义已经满足 a11y 要求 —— 全仓没有 `role=tablist`
先例，而段控本来就是「一组互斥按钮」的语义，切子页正好；也不用为此新造一个 tab 组件。

**位置：先放在内容区顶部、`<Outlet />` 之前**（即子页标题的**上方**）。决策 #2 原本写的是
「紧贴 PageHeader 下方」，但那只在「由 `PageHeader` 承接渲染」时才成立 —— 而 `PageHeader`
（`src/components/layout/PageHeader.tsx:4-12`）只有 `title / description / icon / actions / meta`
五个口，没有 tabs 插槽，要给它加就得动全部 15 个页面的 DOM 与用例。阶段一本就是打样：
先按最省的做法落地、看真机截图，再决定要不要为「标题下方」这个位置付那笔代价。

#### 两处「已就绪 / 需归约」的既有工具（核查结论）

| 函数 | 位置 | 现状 | 嵌套后 |
| --- | --- | --- | --- |
| `isNavItemActive` | `navItems.ts:163-166` | `pathname === path \|\| pathname.startsWith(path + '/')` | ⚠️ 前缀逻辑本身够用，但**签名要改**：收导航项、按 `item.host ?? item.path` 取范围。宿主 `path` 指向子页之后，再拿 `path` 当范围，`/study/writing` 下的「书房」会灭掉 |
| `findNavItem` | `navItems.ts:158-160` | `item.path === pathname` **精确匹配** | ⚠️ `/study/books` 会返回 `undefined`，**需归约到宿主**后再查（实施：复用 `isNavItemActive` 找出命中项，取范围最长的那条） |

`findNavItem` 的归约方式：按 `NAV_ITEMS` 中**最长前缀匹配**，或直接取 `pathname.split('/')[1]`
拼成宿主路径。前者更稳（不依赖路径只分一层）。


**为什么不用路线 B（原路由不变，页内互相挂兄弟链接）**：URL 不分层，命令面板 / 底部 Tab /
g+数字 的收敛都要靠特判；嵌套路由一次到位，后续「健康页跨健身饮食的日历联动」也有挂载点。

### 2.2 数据层：零改动

- 9 个 store、`schemas.ts`、备份 21 个模块、`lm:` 存储键全部原样；
- 不新增任何持久化字段（子页签当前项从 URL 推导，不入库）；
- 合并前后导出文件逐字节同构。

#### 首页 widget 直跳子页：**无需特殊处理**

`HomePage.tsx` 的 widget 跳 `/study/books`（原 `/books`）这类**深层子页** ——
宿主 `StudyLayout` 是它的父路由，**必然一起渲染**，所以子页签条看得见、高亮落在「读书」。

widget 直跳子页**既不丢上下文、也不多一次点击**。**不要**为了「统一」把它们改成跳宿主 ——
那反而会让用户多点一步。这正是嵌套路由的收益。

### 2.4 引用点扫描清单（实施时逐项核）

⚠️ **单纯一条 `grep "'/books'"` 会漏掉三类引用点。** 按「会怎么被漏掉」分类，逐类核：

**① 引号字符串**（原 grep 能抓）

```bash
grep -rn "'/books'\|'/writing'\|'/fitness'\|'/diet'\|'/stats'\|'/review'\|'/goals'\|'/habits'\|'/journal'" src e2e
# 双引号与模板串也要扫：grep -rn "\"/books\"\|\`/books\`"
```

命中：路由表、navItems、e2e 的 goto 与断言、单测的 `MemoryRouter initialEntries`。

**② 函数参数 / 变量**（**grep 抓不到，必须点名核**）

| 位置 | 问题 | 漏了会怎样 |
| --- | --- | --- |
| `src/pages/BooksPage.tsx:291`、`src/pages/WritingPage.tsx:178` | `usePaletteFocus('/books' \| '/writing', ...)` —— 路径是**函数第一个参数**，且作为 focus key | **静默降级**：无 404、无类型错，命令面板聚焦不上 |
| `src/utils/entityIndex.ts:175`（`path: '/books'`）、`:202`（`path: '/writing'`） | 路径作为**实体索引的归属标识** | **静默降级**：全局搜索跳转指向失效。⚠️ 初稿写的「四处（175/202/232/247）」有误 —— 232 / 247 是 `/fitness` 与 `/diet`，属于阶段二 |

这两处**不落库**（已核：`usePaletteFocus` key 仅用于同页注册/查找；`entityIndex` 从 store 现算），
所以改它们**不涉及数据迁移**，「数据层零改动」成立。

**③ 配置对象里的 path 字段**（字段名不含旧路径字面量时 grep 会漏）

| 文件 | 内容 |
| --- | --- |
| `src/components/layout/navItems.ts` | main 组 13 条（第 52/68/76/84/100/108/116/124/132 行） |
| `src/components/layout/BottomTabBar.tsx:11` | `TAB_PATHS = ['/', '/tasks', '/habits', '/stats']` |
| `src/components/layout/CommandPalette.tsx:114/122/130/138` | `QUICK_ACTIONS` 的 `/fitness` `/diet` `/books` `/writing` |

| `src/pages/HomePage.tsx:835/885/925/965` | **`navigate()` 调用**（规划初稿只提了 widget，漏了这四处） |

**⑤ 文档与设置页静态文案**（改路径不会自动同步，只能手工）

| 位置 | 内容 |
| --- | --- |
| `src/pages/SettingsPage.tsx:116` | `SHORTCUT_ROWS` 快捷键说明表 —— `g+数字` 本身是**动态派生**的（`useShortcuts.ts:59` 直接 filter `NAV_ITEMS`），但第 121 行那句「1 首页、2 今日计划、3 读书…」是**手写死的**。改成从 `mainNavShortcuts` 派生即可，手工同步这笔债直接消掉 |

比 404 更难发现。**①③⑤ 靠 grep 能兜底，②必须人工点名核。**

## 4. 风险与克制

1. **数据零风险**：全程不碰 store / schema / 备份；最坏情况回滚也只是导航层。
2. **页面文件不搬目录**：宿主只是容器，import 关系基本不变，diff 可控。
3. **旧路径不删**：全部 `Navigate replace` 重定向，书签、e2e、文档里的旧链接软着陆。
4. **a11y 不回退**：宿主无 h1、子页签条带 role=group + aria-label、当前项 aria-pressed。
   ⚠️ **注意基线盲区**：`src/test/a11y.test.tsx:123-139` 是**直接渲染 15 个页面组件、不走路由**的 ——
   新宿主组件**不在它的覆盖面内**。所以必须**给宿主补独立用例**（直接渲染 `<ModuleHost host="..." />`，
   断言无 h1、子页签条 `role=group`）。阶段二起这组用例按 `MODULE_TABS` 逐模块生成，
   新模块的页面漏登记就抛错 —— 「每阶段跑无障碍基线」这句验收才不是空话。
5. **首屏体积**：新增四个宿主组件都是几十行薄壳，忽略不计；红线 ≤300KB 不变。
6. **重定向无性能代价（已实测）**：在全量懒加载 + `future.v7_startTransition` 下，
   `<Navigate replace>` 是**非紧急更新**，React 把它与目标 chunk 的加载合并在同一 commit，
   **骨架不会闪**（4 组冷加载实测：直连 `/books` 闪 4/4，经重定向 0/4）。
   跳数 3 次 `replaceState`、`history.length` 与直连一致，后退键不回旧路径。
   *局限：机制归因是源码推断（React ESM 作用域无法劫持做反证），但「会不会闪」是实测。*
7. **旧路径永久保留**：不是「暂时留着」，是**永久**。PWA 场景下「确认无旧链接在飞」永远无法确认。
8. **刻意不做**：不合并 store、不改任何页面内部交互、不在这一轮做「健康页跨健身/饮食
   的日历联动」（合并后才有干净的挂载点，列为合并后的可选增强）；
   **也不处理旧路径的深层子路径**（`/books/123` 这类 —— 现在本身就不存在，不算退化；
   将来加详情页时再议），记在此处免得后人以为是漏了。
9. **子页的真相源只有一份**：`MODULE_TABS`。签条、顶栏标题、读屏播报都从它取；不要再写第二份
   子页清单，也不要把子页塞回 `NAV_ITEMS` —— 那会让侧栏、底部 Tab、`g+数字`、命令面板四处
   都得加「排除子页」的判断。
10. **子页切换会重置子页内部状态**（搜索框、筛选、滚动位置）：兄弟路由之间是 unmount / mount。
    已确认为可接受 —— 与「从侧栏点两次重新进这个页面」一致，要保住状态得双份渲染，得不偿失。

### 6.1 签条和页内筛选长得一模一样（建议改）

`wide-books.png` 里，宿主签条（读书 | 写作）和读书页自己的筛选段控（全部 | 想读 | 在读 | 已读）

「列表筛选」被渲染成同一种东西，用户很容易把签条当成又一排筛选 —— 这是 `SegmentedControl`
复用带来的副作用（复用本身是对的，问题是它没有「我是导航」的表达）。

| 方向 | 改动量 | 代价 |
| --- | --- | --- |
| A. 签条改成下划线式（底部指示条、无边框） | 小：`ModuleTabs` 里换一套皮肤 | 与 `SegmentedControl` 分家，多几行样式 |
| B. 上移到顶栏下方、通栏 + 底边框（子导航条） | 中：要动 `Layout` 内容区结构 | 会牵动所有页面，而目前只有书房有签条 |
| C. 保持段控，前面补个「书房」前缀 | 最小 | 只是缓解，同类控件照旧两排 |

倾向 A。

**已定并落地（2026-10-01，`544ec9b`）**：走 A。`ModuleTabs` 换 `variant="underline"`
（`src/components/ui/SegmentedControl.tsx` 现在有 `segment` / `underline` 两套皮肤），
底下一条 2px 指示条、无边框无底色；页内筛选继续用原来的胶囊皮肤。真机复核里两排
控件不再撞脸，「模块内导航」和「列表筛选」一眼分得开。
